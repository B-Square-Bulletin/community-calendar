# 0024. Builds Never Write to Main

Date: 2026-11-22

## Status

Accepted. Extends [0022](0022-generated-artifacts-live-on-archive-branch.md); corrects
the automated-write half of [0002](0002-fork-model-and-main-protection.md).

## Context

ADR 0022 moved per-run generated data to the `archive` branch, but the nightly workflow
still committed a metadata set to `main`: the `feeds.txt` DB export, `cities.json`,
the `report/` pages, `report.html`, `xmlui/config.json` with injected credentials, and
`xmlui/version.txt` from `git describe`. It also reset `cities/*/pending_feeds.txt` to
its template after processing. Each of those is a build output wearing a tracked file's
clothes, so `main` grew on every night the database changed.

Two of them were already broken. `xmlui/version.txt` was rewritten every run but never
staged, so its tracked copy has been stale since 2026-08-03 and the client reload it fed
has been dead since. `docs/prodid.md` is rewritten every run by `scripts/prodid.py` and
never staged either; its tracked copy is from 2026-03-25.

On 2026-11-21 the `main-required-checks` ruleset began requiring eight status checks on
`main` with no bypass actors. A scheduled run's fresh metadata commit has never been
through those checks, so the ruleset rejects the push on every night that has a diff —
structural, though not yet observed in production, since no run has attempted a write
since the ruleset was created. The push-back tolerance added in #315 keeps the archive
publish running after that rejection, but the job still reds and `main` still receives
nothing. Separately, required checks
alone do not close the June 2026 overwrite class: they do not stop a push whose SHA
already passed CI on a feature branch. Only a PR requirement does that.

## Decision

**Invariant: after a build, no tracked file differs from `HEAD`.** The one exception is
`cities/<city>/feeds.txt`: the DB export legitimately rewrites that worktree copy, and it
is never staged (see the `feeds.txt` row below). The invariant is what makes "unchanged
inputs, zero commits" observable rather than aspirational.

1. **No automated process writes to `main`.** The `Commit metadata changes` and
   `Commit processed pending_feeds.txt` steps are deleted, along with the
   `git describe > xmlui/version.txt` write and the `config.json` / `config.local.js`
   injection. `main` changes only through a human PR. No bypass actor, permanent: the
   workflow keeps `contents: write`, used only to force-push the unprotected archive
   branch, so once a PR requirement is in place a future regression to main-writing
   fails closed.

2. **Every file a build used to touch gets a home that does not need a nightly commit.**

   | Path                             | Home                                                                         |
   | -------------------------------- | ---------------------------------------------------------------------------- |
   | `cities/<city>/feeds.txt`        | Frozen seed on `main`; live export on `archive`; ad-hoc human refresh PR     |
   | `cities/<city>/pending_feeds.txt`| Append-only inbox on `main`; the build inserts, never rewrites               |
   | `cities.json`                    | `main`, regenerated by the city-changing PR and guarded by a test            |
   | `xmlui/config.json`              | `main`, hand-maintained; credential rotation is a PR                         |
   | `xmlui/version.txt`              | Deleted; `APP_VERSION` becomes a per-load timestamp                          |
   | `docs/prodid.md`                 | Untracked; published to the archive as `report/prodid.md`                     |
   | `report/<city>/index.html`       | `main` page; changes only with `report_page_template.html` (test-enforced)   |
   | `report.html`                    | `main`, hand-maintained                                                      |

   Three notes. `version.txt`'s deletion (#319) also deletes the `report.html` footer's
   commit link, keeping only the XMLUI engine link. The `report/<city>/index.html` test
   pins only Bloomington today — the only city page there is — and must be looped over
   every `report/*/index.html` before a second city page lands. And
   `xmlui/config.local.js` is gitignored and untracked, so it needs no home; deleting
   the injection write is the whole change.

   `feeds.txt` drift is declared harmless: the DB-less fork path
   (`download_feeds.py`, `seed_feeds_from_txt.py`) still bootstraps from the checked-in
   inventory, the header will say it is a snapshot that may lag (#321), and contributors
   never touch it. City discovery reads the `cities/*/` directories (#321), not the file,
   so a new city runs without a seed refresh.

3. **The guard is per-run, not per-night.** A step after the build fails the run when
   `git diff` shows any tracked path except an unstaged `cities/*/feeds.txt` — the one
   file the invariant excepts and never stages — or when `git diff --cached` shows any
   staged path at all, and names the offending path in `$GITHUB_STEP_SUMMARY`. A quiet
   night proves nothing: with no DB change, "no write" and "no diff" are
   indistinguishable.

4. **`main` requires a PR, permanently.** Add a pull-request rule to
   `main-required-checks`, keep its eight required checks, keep `bypass_actors` empty,
   and keep `strict_required_status_checks_policy` off (no merge queue; strict only adds
   rebase churn). The workflow's `COMMUNITY_CALENDAR` token is dropped: its uses are the
   metadata commit (deleted with the step) and the archive push, which switches to the
   default `GITHUB_TOKEN` — the token that force-pushes the unprotected archive branch.

5. **Failures stay loud and are fixed forward.** The tolerance the deleted write steps
   carried leaves with them, and nothing new gets `|| true` or `continue-on-error`. The
   scraper, RSS and archive-publish tolerance that exists today (`continue-on-error` on
   `Run scrapers from DB`, `|| true` on RSS generation, the archive step's copy
   fallbacks) is deliberate and stays: one bad source must not red the night. The
   archive publish keeps `if: ${{ !cancelled() }}` and starts from the previous
   snapshot, so a failed build still publishes and does not drop cities it did not
   rebuild (0022, #315); what a failed step did not produce comes forward from the
   previous snapshot, so an early failure serves the prior night's report and RSS, not
   fresh ones. A red scheduled run is the signal; recovery is a PR, not a revert.

6. **Rollout order.** (a) Make `pending_feeds.txt` append-only (#322) and delete the
   write steps, with test coverage — the append-only change lands no later than the
   deletion, so the later guard has nothing to red on; (b) re-home the remaining files
   in parallel — `version.txt` removal, `prodid.md` move, `cities.json` guard test,
   `feeds.txt` wording and archive copy; (c) add the
   per-run guard, which is only green once (b) has no tracked file left to dirty;
   (d) add the PR rule and correct AGENTS.md and ADR 0002; (e) one `workflow_dispatch`
   with a real database diff to verify end to end.

## Consequences

- A nightly run with unchanged human inputs produces zero commits. `main` stops growing,
  and no routine PR is ever opened.
- The archive stays the only nightly write. Its snapshot model is unchanged.
- Contributors keep a single path to register feeds (`pending_feeds.txt`), and a failed
  insert retries by staying in the file. The file is append-only: entries are not
  removed for them, and retained entries cost one duplicate POST a night (a no-op).
- A maintainer must run `export_feeds_txt.py` with service credentials and open a PR to
  refresh the seed. The file will say it may lag (#321).
- Rotating Supabase credentials is now a `config.json` PR. A stale key fails visibly
  rather than being silently overwritten nightly.
- Brand components re-download on every page load (the `version.txt` cache-buster is
  gone); that is the local-dev behaviour already.
- The PR requirement lives in repository settings, not in a file. The only automated
  check on it is the pytest sync of check names in `tests/test_workflow_yaml.py`.

## Alternatives Considered

- **A bypass actor for automation, permanent or temporary.** Would let the nightly push
  through, and would re-open the June 2026 overwrite class to whatever token holds it.
  Rejected permanently.
- **Move the whole site to an Actions artifact deploy or a generated site branch.** Keeps
  Pages working but moves the frontend, config and pages for a problem confined to a
  handful of files. Out of scope; Pages keeps serving `main`.
- **Have the build open a PR with its metadata.** A routine PR is exactly what this
  effort rules out, and it would make human inputs (credentials, city list) the subject
  of bot PRs.
- **Stage `version.txt` so it stops being stale.** Turns every night into a commit for a
  reload that has been dead since August.
- **Keep `feeds.txt` as a live export on `main`.** Needs a nightly commit; the frozen
  seed plus ad-hoc refresh keeps the DB-less path without one.
