```bash

docker exec supabase_db_main psql -U postgres -d postgres -c "
  ALTER TABLE feed_health DISABLE ROW LEVEL SECURITY;
```

## Gotchas / Lessons Learned

1. **supabase CLI truncates JWT keys in output** — `supabase status -o env` produces `ANON_KEY="eyJhbG...n_I0"` with literal `...`. The full keys are available inside Docker containers.

2. **Local Supabase RLS blocks test access** — even the `service_role` key can't write via PostgREST unless RLS is disabled AND `GRANT` permissions are applied. This is a local-stack quirk.

3. **`supabase functions serve` on an already-running stack** — when `supabase start` is running (which owns port 54321), `supabase functions serve` integrates with the existing stack rather than starting its own server.

4. **Deno type errors on `Deno.serve()`** — expected in non-Deno LSP. Deno provides these as globals at runtime. The supabase-js type generics also cause issues with `createClient()` return types; using `any` for the supabase parameter in exported functions is pragmatic.
